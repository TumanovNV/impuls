# ADR-001 — Размещение базы знаний проекта

## Статус

Accepted.

## Контекст

Репозиторий ИМПУЛЬС уже содержит `docs/`, однако этот каталог одновременно является источником GitHub Pages: там находятся `index.html`, английская версия сайта, assets, manifest, sitemap, release notes и security audits. Использование той же директории как Obsidian-vault смешало бы публичный сайт, исторические артефакты и внутреннюю навигационную документацию.

Проект также используется несколькими AI coding assistants. База знаний должна быть доступна им без экспорта из отдельного SaaS и должна версионироваться вместе с исходным кодом.

## Решение

Создать отдельный каталог:

```text
/knowledge-base
```

Он является Markdown-first базой знаний и может открываться в Obsidian как отдельный vault.

Основные связи оформляются относительными стандартными Markdown-ссылками, а не только Obsidian-specific wiki links.

## Почему не отдельный репозиторий

Отдельный repository увеличил бы риск рассинхронизации версии документации с кодом и усложнил бы PR, review и AI-context discovery.

## Почему не `/docs`

`/docs` имеет собственный production-контракт как GitHub Pages и уже содержит публичные release/security материалы. Его структура не должна зависеть от организации внутреннего vault.

## Почему не только Obsidian-specific формат

Стандартный Markdown читается GitHub, Obsidian, Claude Code, Codex и другими инструментами. Vault остаётся полезным даже без Obsidian.

## Последствия

Положительные:

- документация версионируется рядом с кодом;
- AI получает предсказуемую точку входа;
- сайт не смешивается с knowledge management;
- ссылки работают в нескольких инструментах;
- изменения кода и документации можно review в одном PR.

Обязательства:

- agent entrypoints должны ссылаться на `knowledge-base/10-ai/AI-INDEX.md`;
- current-state facts не должны бесконтрольно дублироваться по нескольким файлам;
- при значимом изменении код и соответствующая документация обновляются вместе.
