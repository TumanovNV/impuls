# Release QA Evidence — 1.4.14

## Evidence status

This record covers the 1.4.14 release candidate built on top of merged PR #72 (the Power Center redesign, Magic Keyboard/Magic Mouse/Magic Trackpad Bluetooth detection fixes, the Impuls branding refresh, the version-aware What's New fix and the version-aware/periodic voluntary version-statistics follow-up). PR #72's automated Swift and Python suites and the repository's build/knowledge-base workflows passed before merge (509 Swift tests, 0 failures, 3 hardware-dependent skips; 82 Python tests; bundle/codesign/localization/network-boundary checks green).

Beyond PR #72's automated evidence, the release owner performed a real-Mac-mini manual pass of the new Power Center and the Apple accessories it lists (Magic Keyboard, Magic Mouse, Magic Trackpad, AirPods) and confirmed the app worked correctly. That pass is recorded below as scenario-specific evidence only where it actually establishes a concrete pass; it is not stretched into scenarios it did not exercise (multi-display, permission-reset, translation, web-player, or update-check scenarios remain `not-run`).

The private production version-statistics dashboard service was already updated and verified as a separate operational change; it is referenced here in generic terms only, per the public/private operations boundary, and no collector/SQLite schema change is part of this release.

Developer ID signing and Apple notarization were not performed. The release uses the repository's existing ad-hoc distribution path and does not claim Apple notarization.

## Known gaps

- What's New: the version-aware fix is covered by automated regression tests, and a release-preparation build was launched and confirmed to open onboarding/What's New keyed off the real running Bundle version, but no pixel-level manual screenshot exists. This is deliberately **not** recorded as a UI-* manual visual pass.
- Low battery alert: automated regression tests are green, and the real Magic Mouse used during the manual pass was at roughly 24% — above the 20% warning threshold — so the absence of a low-battery notification at that level is expected behavior, not a verified alert pass. PERM-08 remains `not-run`; no manual low-battery alert pass is claimed.
- Multi-display, permission-reset/denied, translation, web-player-navigation and update-check scenarios were not exercised for this candidate and remain `not-run`.
- Developer ID signing and Apple notarization remain unavailable; the release uses the existing ad-hoc distribution path.
- The private production version-statistics dashboard service was confirmed healthy (service active/enabled, health check ok, database integrity check ok, private-network-only access, schema version unchanged, latest-release refresh interval set to 300 seconds) as a separate operational verification; it is not a scenario-specific manual QA row in this table and no collector/SQLite migration is part of this release.

## Release decision rationale

`ship-with-known-gaps` is intentional. PR #72's automated Swift/Python suites and CI workflows are green, and the release owner additionally completed a real Mac mini manual pass of the new Power Center that specifically confirms Magic Keyboard, Magic Mouse, Magic Trackpad and AirPods detection with real (not fabricated) battery data, plus correct desktop no-battery handling and correct top-edge (non-notch) presentation. The remaining scenario-specific manual/hardware/TCC/translation/web-player/update rows were not exercised for this candidate and are recorded as explicit `not-run` gaps rather than inferred passes. Developer ID/notarization remain a known limitation.
