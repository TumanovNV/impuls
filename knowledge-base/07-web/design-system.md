# Website Design System

Дизайн-система маркетингового сайта ИМПУЛЬС. Описывает **presentation layer** canonical
`docs/index.html` (RU source) и всех generated static locale pages, перечисленных в
`Scripts/site-locales/registry.json`.

Это не дизайн-система приложения. Приложение и сайт делят визуальную ДНК — акцентный синий,
шкалу радиусов панели и её кривые движения, — но не являются одним и тем же UI. Токены
интерфейса живут в `Sources/Impuls/UI/Theme.swift`; здесь описано, что из них перенесено,
что расширено и почему.

Единственный источник истины по значениям — сам `docs/index.html`. Этот документ объясняет
намерение и границы; при расхождении сначала устанавливается фактический контракт в CSS.

## Визуальные принципы

1. **Один экран — одна сильная мысль.** Глава несёт один аргумент и одно доказательство.
   Если в главе два тезиса, это две главы или один тезис лишний.
2. **Приложение — главный герой.** Реальные скриншоты продукта крупно. Нарисованный
   фейковый UI запрещён (см. [Website Architecture](website.md), раздел про screenshots).
3. **Ритм задаётся шириной и воздухом, а не линиями.** На странице нет ни одного `<hr>`.
   Разделение глав — расстояние и редкая смена тональной подложки.
4. **Повторяется форма, а не карточка.** Вся страница использует один блочный примитив —
   колонку с волосяной линией сверху. Пять разных глав выглядят одной системой.
5. **Спокойно и дорого.** Ничего не мигает, не парит и не светится. Акцент появляется там,
   где несёт смысл: действие, кромка экрана, начало главы.
6. **Быстро.** Одна самодостаточная страница, без внешних шрифтов, CSS, JS и фреймворков.

## Brand language

Смысл бренда — **движение к верхней кромке экрана**. Панель приложения приходит сверху;
сайт повторяет это ровно тремя приёмами и больше нигде:

| Приём | Где | Реализация |
| --- | --- | --- |
| Акцентный ореол у верхней кромки | `.hero::before`, `.final::before` | `radial-gradient(ellipse at 50% 0, var(--accent-quiet), transparent 68–70%)` |
| Волосяная акцентная линия по верхнему краю продуктовой поверхности | `.stage::before`, `.shot::before` | 1 px `linear-gradient(90deg, transparent, var(--stage-accent-line), transparent)` |
| Та же линия по верхней кромке финальной главы | `.final::after` | 1 px `linear-gradient(90deg, transparent, var(--accent-line), transparent)` |
| Импульс, входящий в заголовок главы | `.chapter .mark` | 2 × 40 px, `linear-gradient(to top, transparent, var(--accent))` |

Правила бренд-приёмов:

- `.mark` **статичен**. Он не анимируется и не зависит от observer'а: элемент, который
  может не появиться, не имеет права быть частью заголовка.
- Ореол и линии — `pointer-events:none` и чисто декоративны.
- Никакого neon/cyberpunk: свечение только через `--accent-quiet` (α ≈ 0.11–0.13).

## Typography

Системный стек, без внешних шрифтов — это часть контракта страницы.

```
--font: -apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display",
        "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif
--mono: ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, monospace
```

Пять ступеней, больше не заводить:

| Роль | Значение | Трекинг / интерлиньяж |
| --- | --- | --- |
| `h1` | `clamp(2.4rem, 1.5rem + 3.9vw, 4.15rem)` | `-.036em` / `1.04` |
| `h2` | `clamp(1.85rem, 1.15rem + 2.5vw, 2.95rem)` | `-.032em` / `1.08` |
| `h3` | `1.125rem` (в `.module-copy` — `1.375rem`) | `-.012em` / `1.35` |
| body | `17px` | `1.6` |
| `.eyebrow`, `.col-k` | `.75rem`, 600, uppercase | `.09–.1em` |

Производные размеры: `.lead` `1.0625rem` → `1.1875rem` от 768 px; hero-lead
`clamp(1.0625rem, .95rem + .55vw, 1.3125rem)`; абзац `.statement-body`
`clamp(1.125rem, 1rem + .8vw, 1.5rem)`.

`font-synthesis-weight:none` и `text-wrap:balance` на заголовках, `text-wrap:pretty`
на длинных абзацах.

**Меры строки.** Hero-lead — 56ch, `.module-copy` — 58ch, ответ FAQ — 62ch,
`.measure` — 34rem, `.chapter` — 46rem, `.statement-body` — 56rem, `.boundaries` — 46rem
(та же величина, что у `.chapter`: леджер и заголовок над ним — одна глава, и их правые
края обязаны совпадать).

Системный стек также является контрактом для CJK-locales: JA и zh-Hans должны получать
нативные системные глифы macOS без отдельного web-font и без смены типографской шкалы.

## Colors

Светлая тема — база, тёмная — переопределение в `@media(prefers-color-scheme:dark)`.
Обратный порядок запрещён: он ломает возможность проверить светлую тему удалением
одного media-блока.

| Токен | Light | Dark |
| --- | --- | --- |
| `--accent` | `#0a5fd6` | `#4d94ff` |
| `--accent-hover` | `#0850b6` | `#6ba6ff` |
| `--accent-quiet` | `rgba(10,95,214,.11)` | `rgba(77,148,255,.13)` |
| `--accent-line` | `rgba(10,95,214,.55)` | `rgba(77,148,255,.6)` |
| `--on-accent` | `#fff` | `#07101f` |
| `--bg` | `#fcfcfd` | `#08090c` |
| `--bg-sunken` | `#f1f3f7` | `#0d0f14` |
| `--surface` | `#ffffff` | `#13161c` |
| `--surface-2` | `#f5f6fa` | `#181c23` |
| `--text` | `#0d0f14` | `#f2f4f8` |
| `--muted` | `#545a68` | `#a2a9ba` |
| `--faint` | `#656c7b` | `#7b8292` |
| `--line` | `rgba(13,15,20,.09)` | `rgba(255,255,255,.10)` |
| `--line-strong` | `rgba(13,15,20,.17)` | `rgba(255,255,255,.20)` |

Фирменный синий ИМПУЛЬС остаётся единственным акцентом. Второго акцентного цвета нет.

**Сцена всегда тёмная в обеих темах.** Снимки панели сняты в тёмном оформлении macOS,
поэтому подложка под ними не спорит с ними за контраст:

```
light  --stage: linear-gradient(168deg, #252a35 0%, #161a22 58%, #10131a 100%)
dark   --stage: linear-gradient(168deg, #1e222c 0%, #12161d 58%, #0c0f15 100%)
       --stage-line:        rgba(255,255,255,.10)
       --stage-ink:         rgba(233,238,248,.62)  /* menu bar */
       --stage-ink-dim:     rgba(233,238,248,.55)  /* caption */
       --stage-accent-line: rgba(77,148,255,.7)    /* the brand hairline */
```

Из этого следует правило: **всё, что лежит на сцене, оценивается относительно сцены,
а не относительно фона страницы, и потому имеет одно значение в обеих темах.**
`--stage-accent-line` живёт здесь именно поэтому. Пока он выводился из
страничного `--accent-line`, в светлой теме получалось `rgba(10,95,214,.55)` поверх
`#252a35` — контраст 1.59 к сцене, то есть тёмно-синяя линия на почти такой же
тёмно-синей поверхности, и фирменный приём там пропадал. Текущее значение даёт
3.08 в светлой теме и 3.32 в тёмной — линия видна одинаково, оставаясь линией
в 1 px, а не свечением.

Страничный `--accent-line` остаётся тематическим: его единственный потребитель —
`.final::after`, и он лежит на `--bg-sunken`, а не на сцене.

`--faint` — нижняя граница светлоты. Он несёт eyebrow'ы, meta-строку, `.module-note`
и футер, то есть обычный body-текст, и обязан проходить 4.5:1 **и** на `--bg`, **и**
на `--bg-sunken`. См. [Accessibility](#accessibility).

## Spacing philosophy

Сетка 4 pt приложения, продолженная вверх до расстояний между главами:

```
--s1 4   --s2 8   --s3 12  --s4 16  --s5 24  --s6 32
--s7 48  --s8 64  --s9 96  --s10 128  --s11 160
```

Правила:

- Ритм главы: `section { padding-block: clamp(80px, 9vw, 160px) }`.
- Внутри главы шаг между смысловыми частями: `clamp(40px, 5vw, 64px)`.
- Закрывающая строка главы (`.closing`): `clamp(56px, 7vw, 96px)` — она должна читаться
  как отдельная мысль, а не как продолжение предыдущего абзаца.
- Радиусы: `6 / 10 / 14 / 22` — шкала панели из `Theme.swift`; `30` и `pill` добавлены
  для маркетинговых поверхностей. Переносить каждый радиус приложения на сайт не нужно.

## Layout / container rules

Ширина — главный ритмический инструмент страницы. Главы чередуют колонки по ширине,
а не «текст слева / скриншот справа».

| Контейнер | Ширина | Назначение |
| --- | --- | --- |
| `.wrap` | `1180px` (`1340px` от 1800 px) | базовая колонка |
| `.wrap.wrap-wide` | `1440px` (`1640px` от 1800 px) | продуктовые сцены |
| `.chapter` | `46rem` | заголовочный блок главы |
| `.measure` | `34rem` | узкая читаемая колонка |

Горизонтальный gutter — переменная `--gutter`: `20px` → `40px` (≥768) → `56px` (≥1280).
Отрицательные отступы full-bleed-элементов считаются от неё, а не от литерала.

**Левый край страницы един.** Центрированные главы симметричны и его не ломают.
Левовыровненную узкую колонку центрировать нельзя — это читается как отступ, а не как
композиция; поэтому `.boundaries` ограничен `max-width`, а не помещён в центрированный
контейнер.

Блочный примитив один — `.cols`: колонка с волосяной линией сверху, без карточки,
без рамки, без подложки. Модификаторы `.cols-3` и `.cols-4`. Его используют hero-pillars,
границы питания, факты поведения, факты открытости и шаги установки — пять глав, один ритм.

## Breakpoints

| Точка | Что меняется |
| --- | --- |
| `max-width: 359px` | скрывается иконка бренда, чтобы locale-strip и «Скачать» не вытеснялись за viewport |
| `max-width: 599px` | hero-CTA в одну колонку на всю ширину |
| `640px` | `.cols` → 2 колонки |
| `max-width: 699px` | скрывается текст wordmark; locale-strip получает собственный горизонтальный scroll; скриншоты панятся вместо уменьшения; full-bleed сцены; появляется `.pan-hint` |
| `max-width: 759px` / `760px` | чипы модулей: скролл-полоса → центрированный wrap |
| `768px` | gutter 40 px; `.lead` крупнее |
| `840px` | `.cols-3` → 3 колонки |
| `860px` | `.steps` → 3 колонки |
| `1024px` | `.cols-4` → 4 колонки; появляется nav-меню |
| `1280px` | gutter 56 px |
| `1800px` | контейнеры расширяются, чтобы страница не была макетом в пустоте |

Спроектированные ширины: **390 / 430 / 768 / 1024 / 1440 / 1920**. Дополнительно language
selector обязан оставаться без page-level overflow на 320 px.

## Buttons

```
.btn      min-height 46px, padding 0 24px, radius --r-m (10px), 15px/500
.btn-sm   min-height 36px, padding 0 16px, 14px
.btn-lg   min-height 54px, padding 0 32px, 16px
```

Радиус 10 px, а не pill: это ДНК панели и это спокойнее, чем маркетинговая таблетка.
Pill остаётся только у чипов селектора модулей, где он маркирует компактный контрол.

- `.btn-primary` — `--accent` + мягкая акцентная тень; **один на экран**.
- `.btn-ghost` — рамка `--line-strong`, прозрачный фон.
- На ширине < 600 px кнопки hero-CTA растягиваются на всю ширину и складываются в колонку.
- Все интерактивные цели ≥ 44 px по высоте (кроме `.btn-sm` в шапке — 36 px, компенсируется
  padding'ом строки).

## Navigation

Шапка — `position:sticky`, высота **56 px**, полупрозрачный `--bg` с `backdrop-filter`.
Высота — обещание: навигация не должна занимать заметную долю первого экрана на 390 px.

- Ссылки разделов показываются от 1024 px; ниже остаются бренд, переключатель языка и
  кнопка скачивания.
- `header.stuck` добавляет нижнюю волосяную линию при скролле > 8 px.
- Переключатель RU/EN/DE/FR/ES/JA/简 — **навигация между самостоятельными статическими
  страницами**, а не runtime-тоггл перевода. Public code, label и path принадлежат
  `Scripts/site-locales/registry.json`; canonical control синхронизирует
  `Scripts/sync-site-locales.py`, generated control строит `Scripts/build-site-locale.py`.
- Locale code нельзя считать URL-путём: `zh-Hans` публикуется по `/zh-hans/`.
- Ни один язык не скрывается ради тесной шапки. На narrow viewport прокручивается только
  `.lang`, а кнопка Download остаётся отдельной и всегда доступной.

## Product screenshot presentation

Две формы, больше не заводить.

**`.stage` — экран Mac.** Скруглён только сверху, нижняя граница уходит за край главы,
внутри строка меню (`.menubar`) и панель, приходящая сверху. Используется один раз — в hero.

**`.shot` — самодостаточная сцена.** Скруглена со всех сторон, тень `--shadow-scene`,
изображение прижато к нижнему краю. Используется в главах «Действия», «Питание» и в
галерее модулей.

Обе несут акцентную волосяную линию по верхнему краю — точку, откуда выходит панель.

Правила:

- Только реальные снимки продукта; демо-данные подписываются (`.stage-caption`).
- Реальные capture-наборы сейчас `assets/screens/ru/*` и `assets/screens/en/*`. Generated
  locale config задаёт `screenshot_locale`; DE/FR/ES/JA/zh-Hans пока честно используют
  EN captures, пока реальные снимки соответствующих интерфейсов не подготовлены. Fake
  localized UI запрещён. `alt` — это контент и переводится отдельно для каждой page locale.
- Панель имеет пропорцию ≈ 2.7 : 1. Ниже 700 px её **не сжимают**: кадр держит
  `min-width: 620px` и скроллится внутри себя, страница вбок не едет. Появляется
  `.pan-hint` — подсказка о свайпе.
- `.pan-hint { display:none }` объявляется **до** media-блока, который включает его на
  телефоне. Обратный порядок при равной специфичности выигрывает и гасит подсказку
  навсегда — так она и не показывалась ни в одной сборке до 1.4.13.
- Подсказка принадлежит **снимку**, а не главе: она стоит соседом своего `.shot`.
  В галерее модулей это означает по копии внутри каждого `article.module`, а не одну
  под всем переключателем — там она оказывалась на два абзаца ниже кадра, к которому
  относится. Шесть копий в разметке никогда не дают шести подсказок на экране: со
  скриптом показан ровно один модуль, без скрипта каждый из шести стопкой несёт
  подсказку к своему собственному снимку.
- Стрелка выравнивается по **первой** строке (`align-items:flex-start` + оптический
  сдвиг), а не по центру блока: на узком экране подпись переносится на две строки, и
  центрированный значок повисает между ними.

## Section composition

Порядок глав: **Hero → проблема → Действия → Модули → Питание → Экраны → Приватность →
Открытость → Установка → FAQ → финальный CTA.**

| Глава | Форма |
| --- | --- |
| Hero | центрированный текст → продукт во всю ширину → 3 pillars → meta-строка |
| Проблема (`.statement`) | одна левая колонка крупным кеглем, **без продуктовой поверхности** |
| Действия | шапка слева → широкая сцена → 3 равные колонки шагов |
| Модули | центрированная шапка → чипы → одна сцена во всю ширину → копия по центру |
| Питание | шапка слева → широкая сцена → 4 колонки границ |
| Экраны | центрированная шапка → 4 колонки → закрывающая строка |
| Приватность | шапка слева → леджер из 5 строк с акцентными глифами |
| Открытость | шапка слева → 4 колонки с двумя CTA |
| Установка | шапка + CTA → 3 шага → hashbox → команда |
| FAQ | центрированная шапка → аккордеон 48rem |
| Финал | центрированный CTA с ореолом и линией |

Тональные подложки (`.band`, `--bg-sunken`) чередуются: проблема, модули, экраны,
открытость, финал. Две подложки подряд не ставятся.

**Hero.** Технические факты (macOS, версия, размер, открытый код) стоят **после**
продуктового визуала. Читатель, ещё не увидевший приложение, не имеет применения его
размеру в мегабайтах.

## Motion

Кривые и длительности взяты из `Theme.PanelMotionPlan`:

```
--ease-open  cubic-bezier(.16, 1, .3, 1)
--ease-close cubic-bezier(.4, 0, 1, 1)
--dur-open   .22s
--dur-close  .16s
```

| Движение | Что делает |
| --- | --- |
| `panel-drop` | панель выезжает в hero из-за строки меню, `.5s`, задержка `.15s` |
| `module-settle` | переключённый модуль оседает на 6 px, `--dur-open` |
| `.reveal` | блок приходит снизу на 14 px при появлении в кадре |

**Главное правило движения: только `transform`, никогда `opacity`.**

В таблице стилей нет ни одного правила `opacity:0`. Контент, спрятанный за анимацию или
за IntersectionObserver, — это контент, который может не появиться; в этом проекте это
уже стоило трёх дефектов (невидимая глава «Действия» без JS, скрытые блоки «Поведения»
внутри `-8%` нижнего поля observer'а и hero-панель, зависящая от того, что анимация
действительно проиграет).

Вся крупная моторика обёрнута в `@media(prefers-reduced-motion:no-preference)`.
При `reduce` не остаётся ни анимаций, ни смещений, ни `scroll-behavior:smooth`.
Мелкие hover/state-переходы (цвет, фон, поворот шеврона FAQ) не гасятся — они не являются
motion-анимацией в смысле WCAG 2.3.3.

## Dark / light rules

- Тема следует `prefers-color-scheme`. Переключателя нет и не планируется.
- Светлая — база, тёмная — переопределение. Проверять светлую тему можно удалением
  всех `@media(prefers-color-scheme:dark)` блоков из CSSOM.
- Проверяются **обе** темы для всего, что затронуто.
- **Ловушка `background-clip`.** Для текста с градиентной заливкой в тематических
  переопределениях используется `background-image`, а не сокращение `background`:
  сокращение сбрасывает `background-clip` в `border-box`, заголовок исчезает за цветным
  прямоугольником. На текущей странице градиентного текста нет намеренно; правило
  сохраняется для любого будущего элемента, который начнёт клипать фон по тексту.
- Сцена остаётся тёмной в обеих темах.

## Responsive rules

- **Никакого горизонтального скролла страницы ни на одной ширине.** Проверяется как
  `document.documentElement.scrollWidth === clientWidth`.
- Всё, что выходит за вьюпорт, обязано лежать внутри контейнера с собственным
  `overflow-x:auto` (сцена скриншота, полоса чипов, seven-locale strip) и иметь понятную
  область прокрутки, не расширяя `documentElement`.
- `minmax(0,1fr)` в grid-треках и `min-width:0` на grid-элементах обязательны: элемент
  грида по умолчанию `min-width:auto` и отказывается сжиматься ниже минимума контента,
  из-за чего кадр с `min-width:620px` однажды вытолкнул всю секцию за 390 px экран.
- Ряд из трёх элементов до 840 px остаётся одной колонкой: две из трёх рядом оставляют
  сироту во второй строке.
- На телефоне продуктовая сцена уходит в full-bleed на всю ширину вьюпорта.
- Header при семи locale links не имеет права решать тесноту скрытием языка или Download:
  до 699 px скрывается wordmark text и прокручивается только `.lang`; до 359 px можно
  скрыть brand icon. Все семь ссылок остаются в DOM и доступны без JavaScript.

## Accessibility

Проверено на текущей сборке:

- Один `<h1>`; уровни заголовков идут без пропусков; landmark'и `header` / `main` /
  `footer` / `nav` на месте; skip-link уводит на существующий `#main`.
- У каждого продуктового изображения есть содержательный `alt`; у декоративной иконки
  бренда `alt=""`.
- Селектор модулей — корректный `tablist` / `tab` / `tabpanel` с roving `tabindex`,
  стрелками влево/вправо/вверх/вниз и закольцовкой.
- Языковой selector — обычные ссылки с `hreflang` и `aria-current`; он не зависит от JS,
  а прокрутка narrow-strip не удаляет ссылки из tab order.
- `:focus-visible` даёт `2px solid var(--accent)` с отступом 3 px на всех интерактивных
  элементах.
- Страница работает без JavaScript: чипы скрыты, все шесть модулей видны стопкой, ссылки
  скачивания указывают на реальный DMG, версия/размер/имя файла/SHA статичны и верны.

Контраст (WCAG 2.1, порог 4.5:1 для обычного текста):

| Пара | Light | Dark |
| --- | --- | --- |
| `--text` на `--bg` | 18.70 | 18.08 |
| `--muted` на `--bg` | 6.74 | 8.46 |
| `--muted` на `--bg-sunken` | 6.22 | 8.14 |
| `--faint` на `--bg` | 5.14 | 5.17 |
| `--faint` на `--bg-sunken` | 4.74 | 4.97 |

здесь не аргумент: `--faint:#757c8c` выглядел нормально и давал 4.08 / 3.77.

## Anti-patterns

Чего сайт ИМПУЛЬС не делает:

- **Не прячет контент за `opacity`.** Ни `opacity:0` в стилях, ни зависимости появления
  от observer'а.
- **Не выглядит как документация или dashboard.** Никакого sticky-рейла настроек,
  никакой сетки одинаковых плиток вместо рассказа.
- **Не чередует «текст слева / скриншот справа».** Две колонки — только там, где они
  реально дают преимущество; ритм задают ширина и выравнивание.
- **Не сыплет мелкими glassmorphism-карточками, floating badges и случайными градиентами.**
- **Не рисует фейковый UI приложения.** Только реальные снимки.
- **Не заводит второй акцентный цвет** и не уходит в neon/cyberpunk.
- **Не подключает внешние шрифты, CSS, JS или фреймворки.** Страница обязана
  отрисоваться одним запросом.
- **Не показывает пачку технических фактов до продуктового визуала.**
- **Не ставит `<hr>` между главами** — расстояние делает это лучше.
- **Не хардкодит релиз.** Версия, ссылка и SHA приходят из механизма релиза.
- **Не правит generated locale HTML руками.** EN/DE/FR/ES/JA/zh-Hans pages строит общий generator.
- **Не строит public URL из locale code.** Code и registry path — разные поля.
- **Не поддерживает второй список public locales** вне `Scripts/site-locales/registry.json`.
- **Не добавляет ступень в типографскую шкалу** ради одного блока.

Плюс якоря, по которым работают скрипты:

- `Scripts/sync-site-release.py` — объект `FALLBACK_RELEASE`, элементы
  `[data-release="version-label"|"size"|"filename"]`, `<code id="hash">`, ссылки
  `[data-conversion="download"]` и релизные поля JSON-LD.
- `Scripts/sync-site-locales.py` — canonical `hreflang`, OG locale cluster,
  `WebSite.inLanguage`, language control, runtime labels и startup locale flow.
- `Scripts/build-site-locale.py` — атрибуты `data-i`, screenshot `data-shot`, head/schema

Атрибуты `data-i` не вкладываются друг в друга и не ставятся на void-теги.
