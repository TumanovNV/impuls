# Impuls 1.3.0 Web Music Security Review

## Scope

This review covers the new web-music boundary in `WebMusicPlayer.swift`, source
selection, Apple Music adapter changes, permissions, local website data, and the
CI rules that distinguish explicit web playback from unsolicited networking.
The Sparkle update trust chain is unchanged.

## Security decision

Impuls does not use an unofficial catalogue or playback API. Web sources open
the provider's own HTTPS site in the system WebKit engine. This preserves the
provider's authentication, subscription, DRM, regional, and playback decisions
instead of copying credentials or reimplementing protected delivery.

The web view is lazy. `MediaController` stores only an optional reference and
constructs `WebMusicPlayer` inside `openSelectedSource()`. Selecting Yandex
Music, VK Music, YouTube Music, or Spotify changes local UserDefaults only. CI
greps the construction site and the PR smoke test launches the signed bundle for
ten seconds, then fails if `lsof` observes any socket.

## Navigation and message boundaries

- initial URLs are fixed HTTPS provider pages;
- top-level navigation is accepted only for the selected provider and a bounded
  set of authentication domains;
- unrelated HTTP(S) links are handed to the default browser rather than loaded
  in the embedded player;
- script messages are accepted only from the current web view while its main URL
  is still within the selected source boundary;
- the payload version and page URL are validated;
- title, artist, and album are each limited to 512 characters;
- duration and position must be finite, nonnegative numbers, and position is
  clamped to duration;
- no input, password, cookie, local-storage value, token, or page body is read.

The bridge reads Media Session metadata, known now-playing labels, and the active
HTML media element. It can play, pause, seek, or click bounded transport-control
candidates only after an Impuls button action. It does not inject native code,
load a private framework, or bypass the site's own JavaScript and media policy.

## Local data and permissions

The selected source is stored in UserDefaults. WebKit's default website data
store retains the provider's ordinary cookies and site data locally so a user
can remain signed in. Playback metadata is held in memory and is not uploaded by
Impuls. The provider receives the ordinary network data associated with opening
its site and remains governed by its own privacy terms.

Accessibility is no longer requested by the Music module. Apple Events
Automation remains only for the installed Apple Music application. Web players
do not receive either macOS permission.

## Native Apple Music fallback

Private system-wide Now Playing APIs remain prohibited. Apple Music first uses
its scripting interface. Bounded distributed player-change metadata provides a
second path when a transient scripting response is empty. Unknown script errors
are surfaced as an unreadable state instead of being misreported as no playback.

## Known limitations

Provider markup, Media Session behaviour, authentication, and WebKit playback
support can change without an Impuls release. Service-specific button selectors
are a fallback and may stop matching. Impuls must not respond by collecting
tokens, reverse-engineering protected APIs, weakening navigation checks, or
adding private macOS media frameworks.

## Verification

- local diff, YAML, shell, localization, and inline JavaScript validation;
- unit tests for host lookalikes, HTTPS-only navigation, bounded payloads,
  cross-provider rejection, position clamping, source persistence, and Apple
  Music notification parsing;
- macOS CI compilation and full Swift test suite;
- signed entitlement inspection;
- no-network launch smoke test;
- DMG and update-ZIP construction, signature verification, and SHA-256 checks.
