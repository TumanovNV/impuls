# Impuls 1.2.6 — security and performance review

Review date: 2026-08-09

Scope: application source, main-thread and memory budgets, clipboard and file
processing, local persistence, Calendar and media bridges, update checks,
feedback collection, tests, CI, packaging, and release controls.

## Threat model

The review treats clipboard values, dragged files, image metadata, local JSON,
backup documents, Calendar fields, media artwork, update responses, redirects,
and feedback text as untrusted or potentially excessive. Same-user filesystem
races and damaged local state are included because they can cause data loss or
resource exhaustion even without privilege escalation.

## Findings addressed in 1.2.6

| Priority | Finding | Resolution |
|---|---|---|
| High | Generated-file Undo trusted size, modification date, and resource identity. A same-size edit with a restored timestamp could be mistaken for the original result and moved to the Trash. | The record now includes a streaming SHA-256 digest and verifies a stable metadata snapshot before and after hashing. Digest work runs outside the UI thread and refuses files above a 512 MiB Undo budget. |
| Medium | Clipboard screenshots up to 64 MiB were written atomically on the main thread; rapid image changes could retain an unbounded queue of large payloads. | Screenshot I/O is serialized on a utility queue, at most two saves may be pending, and folder usage/clearing runs on the same ordered queue. |
| Medium | Compact rows repeatedly trimmed, replaced newlines in, or hashed complete clipboard, snippet, and note values. JSON classification also sorted and serialized the complete object, while empty Actions searches built the entire local corpus. | UI projections, query lengths, and search corpora are bounded; snippet IDs are compact; classification now parses without formatting; the empty Actions state builds only its ten visible rows; one result snapshot is shared per SwiftUI render. |
| Medium | Note JSON encoding and atomic writes executed on the main thread after typing pauses. | Saves are generation-coalesced and encoded on a serial utility queue. Shutdown drains the queue and writes the exact final snapshot synchronously. |
| Medium | Player notifications could accumulate AppleScript refreshes, timers were recreated after metadata events, and full artwork was handed to AppKit. | Only one refresh plus one coalesced follow-up may exist, the active timer is reused, artwork is capped at 16 MiB, dimension-checked, and downsampled to 512 pixels through ImageIO. |
| Medium | Link detection scanned complete Calendar location and notes fields and the seven-day result set had no explicit count budget. | Link scanning is capped at 32,768 characters per field, only known credential-free HTTPS provider URLs pass, and at most 250 sorted meetings are materialized. |
| Low | The bounded file reader could overflow `remaining + 1` if reused with `Int.max`. | The read size now branches before addition; a regression test exercises the maximum integer budget. |
| Low | Imported clipboard-exclusion identifiers were count-limited but not length-, candidate-, or character-validated. | At most 500 bounded candidates are inspected; retained identifiers are limited to 255 UTF-8 bytes and ASCII bundle-identifier characters before persistence. |
| Informational | Repository feedback forms exposed inconsistent dimensions and the bug form contained a stale version example; blank issues bypassed the structure entirely. | Problem, idea, and experience forms now align area, frequency, rating, and version context where applicable. Blank issues are disabled; private vulnerability reporting remains separate. |

## Controls re-verified

- application networking remains confined to `UpdateService.swift` and the
  fixed GitHub latest-release API URL;
- redirects, response URLs, response size, release tag URL, timeouts, cookies,
  cache use, and parallel update checks remain restricted;
- feedback contains no networking API, previews the complete report, copies it
  only after an explicit action, and opens only the exact Impuls issue URL;
- feedback diagnostics remain limited to Impuls version, macOS version, and CPU
  architecture; user content, paths, logs, serial numbers, and identifiers are
  not collected automatically;
- concealed and Impuls-internal pasteboard markers are detected by type without
  materializing marker payloads;
- clipboard persistence remains opt-in, AES-GCM encrypted, and keyed by a
  device-only macOS Keychain item;
- file transformations create sibling outputs and do not overwrite sources;
- local reads, image dimensions, image bytes, text search, Calendar fields,
  generated-file hashing, and pending screenshot writes have explicit budgets;
- package dependencies remain empty; GitHub Actions are pinned to commit SHAs;
- CI rejects private MediaRemote/perl injection paths and network APIs outside
  the update service.

## Feedback assessment

The implementation is privacy-correct and analytically usable: category, area,
frequency, rating, summary, details, optional basic diagnostics, preview, public
submission warning, copy fallback, and private security reporting are present.
No user issue had been opened in the repository at review time. That is not
evidence of satisfaction or failure; conversion and response-time KPIs become
meaningful only after real submissions exist.

## Residual risks and accepted limitations

1. Public builds remain ad-hoc signed and not notarized. Developer ID,
   Hardened Runtime, notarization, and certificate-rotation procedures remain
   the highest-priority distribution-security work.
2. Impuls is not App Sandbox constrained because shelf workflows operate on
   files selected by the user.
3. Notes and snippets are plaintext local JSON. FileVault and the protected
   macOS account remain their at-rest boundary; secrets should not be stored.
4. Automatic crash upload remains absent by design. Stability evidence depends
   on tests and voluntary reports until a separately reviewed opt-in design
   exists.
5. GitHub issues are public and require an account. The app warns, previews,
   preserves a copy for manual paste, and routes vulnerabilities privately.

## Release gate

Production requires the macOS 15 workflow to pass all Swift tests, release
compilation, localization, privacy/network/static budgets, bundle identity,
entitlements, signature validation, and DMG verification. After merge, the tag
must target the production commit and the SHA-256 of a separately downloaded DMG
must match the published checksum.
