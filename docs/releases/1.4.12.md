# Impuls 1.4.12

## Нативный индикатор батареи в Menu Bar

- При выборе батареи в статусном элементе Menu Bar теперь показывает системный
  SF Symbol батареи и процент, а не логотип Impuls. Заполнение символа следует
  реальному уровню, а сам индикатор использует системные semantic colors:
  зелёный от 60 %, оранжевый от 20 до 59 %, красный ниже 20 %.
- Во время подтверждённой зарядки рядом с батареей появляется нативный
  `bolt.fill`; Unicode emoji не используется. Полностью заряженное или просто
  подключённое устройство не выдаётся за заряжающееся.
- Этот же renderer используется для батареи Mac и выбранного совместимого
  Apple-устройства. Проценты, tooltip и VoiceOver-описание остаются доступными,
  а режимы логотипа Impuls, плеера и Automatic сохраняют прежнюю policy.

## Статистика версий

- Добровольный version heartbeat выполняется не чаще одного раза в час.
- Приватный owner dashboard автоматически определяет последний стабильный
  GitHub Release через фиксированный API, атомарно сохраняет валидный результат
  локально и использует последний успешный cache при недоступности GitHub.

# Impuls 1.4.12

## Native Menu Bar battery indicator

- When Battery is selected for the Menu Bar status item, Impuls now shows a
  system SF Symbol battery and its percentage instead of the Impuls logo. The
  glyph follows the actual level and uses semantic system colours: green from
  60%, orange from 20% through 59%, and red below 20%.
- A native `bolt.fill` appears beside the battery only while charging is
  confirmed; no Unicode emoji is used. A fully charged or merely plugged-in
  device is not presented as charging.
- The same renderer serves This Mac and a selected compatible Apple device.
  Percentages, tooltip and VoiceOver description remain available, while the
  Impuls logo, player and Automatic modes keep their existing policy.

## Version statistics

- The optional version heartbeat attempts no more than once per hour.
- The private owner dashboard automatically determines the latest stable GitHub
  Release through a fixed API, atomically persists a valid result locally, and
  retains the last successful cache while GitHub is unavailable.
