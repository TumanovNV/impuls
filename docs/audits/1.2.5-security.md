# Impuls 1.2.5 — security and performance review

Review date: 2026-08-09
Scope: application source, local persistence, file and clipboard processing,
update checks, feedback flow, build and release controls.

## Threat model

The review treats the following inputs as untrusted even though Impuls is a
local application:

- images and files dragged to the shelf;
- text, images, file references, and concealed entries exposed by the system
  pasteboard;
- imported backup files and locally editable JSON stores;
- responses and redirects received by the optional GitHub update check;
- text entered into the public feedback report;
- release artifacts produced by GitHub Actions.

## Findings addressed in 1.2.5

| Priority | Finding | Resolution |
|---|---|---|
| High | A crafted image with extreme dimensions could be fully decoded before a resource budget was enforced, causing excessive memory pressure or termination. | Full-resolution operations validate dimensions against a 64-million-pixel budget before decode. Larger originals can still use the thumbnail resize path. Tests cover accepted and rejected dimensions. |
| Medium | Clipboard history accepted text and encoded images without an upper bound, allowing excessive retention and persistence work. | Text is capped at 512 KiB, encoded images at 64 MiB, and image dimensions are validated before conversion or retention. Restored history uses the same rules. |
| Medium | A completion-handler update request could buffer an unknown-length or chunked response before its 512 KiB post-download check ran. | A data delegate now accumulates chunks into a bounded buffer and cancels immediately at the limit. Redirects and final responses remain restricted to the exact API endpoint; the release page must exactly match its tag. |
| Medium | Backup, notes, snippets, shelf image data, and encrypted clipboard files used a size preflight followed by a separate whole-file read. A file changed between those operations could bypass the memory budget. | All affected reads now stream through a shared bounded reader that never holds more than the configured limit. |
| Medium | The Calendar module could fall back to an arbitrary URL supplied by an event, including a non-HTTPS or custom scheme. | Join links now require HTTPS, no credentials or custom port, and an allow-listed meeting-provider host. |
| Medium | Optional clipboard persistence encrypted and wrote the complete archive synchronously for every captured change. A large history could stall the UI and amplify disk writes. | Saves are coalesced for 750 ms, encoded and written on a serial utility queue, and explicitly flushed at shutdown. Disable/delete waits for in-flight work and prevents a stale save from recreating the archive. |
| Low | Actions search and content classification repeatedly normalized or parsed an entire large clipboard string on the main actor. | Structured classification is capped at 64 KiB; search uses at most 16,384 characters per result; summaries scan only through the displayed prefix. |
| Low | JPEG and HEIC bytes copied from the shelf could be declared as TIFF on the pasteboard. | Inline image data now uses its actual Uniform Type Identifier and is capped at 64 MiB; the file reference remains available for larger files. |
| Low | Creating a new Core Image context for every background-removal operation and retaining temporary objects across a batch added avoidable memory pressure. | A reusable Core Image context is shared, and each file operation runs inside a scoped autorelease pool. |
| Informational | There was no visible, structured feedback path, so defect discovery depended on users finding the repository themselves. | A voluntary, previewable report opens only the fixed Impuls GitHub issue page. It uses no in-app upload or telemetry and collects category, area, frequency, rating, summary, and details. |

## Controls verified

- networking APIs remain confined to `UpdateService.swift`;
- feedback has no networking API and only opens the exact HTTPS Impuls
  new-issue path after a user action;
- feedback diagnostics are allow-listed to Impuls version, macOS version, and
  processor architecture;
- clipboard contents, notes, file names, paths, calendar data, logs, serial
  numbers, and device identifiers are not collected for feedback;
- concealed password-manager pasteboard entries remain excluded;
- optional clipboard persistence remains AES-GCM encrypted with a random
  device-only Keychain key and is disabled by default;
- repeated clipboard changes are coalesced and encryption/write work does not
  execute on the main thread;
- Calendar join links are restricted to known HTTPS meeting-provider hosts;
- transforming file operations create unique sibling files and do not replace
  originals;
- file-operation Undo remains conservative and refuses changed results;
- CI rejects private MediaRemote integration, process injection, and networking
  outside the update service;
- CI now checks feedback boundaries, issue templates, release notes, and the
  consistency of website and application versions.

## Residual risks and accepted limitations

1. **Distribution trust:** public builds are still ad-hoc signed and not
   notarized. Users cannot cryptographically verify an Apple Developer ID, and
   Gatekeeper requires manual approval. Developer ID signing, Hardened Runtime,
   notarization, and a documented certificate-rotation process remain the most
   important release-security work.
2. **Application sandbox:** Impuls is not distributed through the Mac App Store
   sandbox. Its file shelf and cross-application workflows intentionally operate
   on user-selected files. This increases the importance of fixed network
   boundaries, conservative file writes, and signed distribution.
3. **Local plaintext stores:** notes and snippets are not separately encrypted
   by Impuls. FileVault and a protected macOS account remain the at-rest security
   boundary. Secrets, recovery codes, and private keys should not be stored in
   these modules.
4. **Crash visibility:** there is no automatic crash upload. This protects
   privacy but means stability evidence depends on automated tests and voluntary
   reports. A future crash-report mechanism would require separate opt-in,
   redaction, retention, and processor documentation before implementation.
5. **Public feedback:** GitHub issues are public and require a GitHub account to
   submit. The app warns the user, previews the exact report, and keeps a copy on
   the pasteboard when the prefilled URL would be too long.

## Release gate

The release is ready for user testing only after the `macos-15` workflow passes
Swift tests, application compilation, localization checks, network and feedback
boundaries, bundle identity, entitlements, ad-hoc signature validation, and DMG
creation. Production publication requires a green test DMG followed by a
verified release workflow and a SHA-256 match against the downloaded production
asset.
