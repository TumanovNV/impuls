# Impuls 1.3.1 Web Music Boundary Review

Supplements `1.3.0-web-music-security.md`. Only the parts that changed are
restated here; everything not mentioned stands as reviewed in 1.3.0.

## Why the boundary moved

1.3.0 applied one allow-list to every `WKNavigationAction`. WebKit calls that
delegate for subframe navigations too, so a captcha, a consent frame or a
sign-in widget on a third-party host was cancelled along with everything else,
and the provider page rendered blank. The list was not protecting the metadata
boundary — it was breaking the pages it was meant to open.

## Where the boundary sits now

- **Main frame** — unchanged in spirit and slightly widened in hosts. HTTPS
  only, restricted to the selected provider's domains plus the sign-in hosts
  that provider redirects to (`passport.yandex.*`, `id.vk.*`,
  `accounts.google.com`). An unrelated link is handed to the default browser.
- **Subframes** — `https`, `about`, `blob` and `data` are allowed; anything
  else, including `file:`, is cancelled. A subframe cannot reach the Impuls
  message handler because the bridge script is installed with
  `forMainFrameOnly: true`, so widening this does not widen what Impuls reads.
- **State reports** — tightened. A payload is accepted only when the web view's
  main URL is an **HTTPS** page inside the selected source. 1.3.0 accepted
  `about:blank` here through the navigation predicate; the failure page and
  popup shells use that URL, so it is now navigable but never authoritative.
- **Popups** — `createWebViewWith` opens a real window instead of loading the
  request into the main view. The popup carries the same configuration, is held
  to the same main-frame list, and is excluded from state and artwork messages.

## User agent

`applicationNameForUserAgent` now appends `Version/<n> Safari/605.1.15`. The
engine token stays whatever WebKit reports; only the Safari product token is
added, and `<n>` is read from `/Applications/Safari.app` and accepted only if it
consists of digits and dots. Nothing is invented about the platform, and no
request is made to discover it.

## Artwork

The page fetches the cover from its own origin under its own credentials
policy (`credentials: 'omit'`) and hands the bytes to Impuls as base64. The app
performs no network call, which keeps the CI network boundary intact. The
payload is bounded three times: 4 MB at the blob, 6 MB at the encoded string,
and `PlayerBridge.maximumArtworkBytes` after decoding, and the bytes then go
through the same ImageIO dimension validation as Apple Music artwork. A cover
is requested only when its URL changes, and only for the currently selected
source.

## Transport, and why it reaches into the page

Three of these services expose no scriptable interface, so the transport has to
act through the page. The bridge tries three routes in order and verifies the
result rather than assuming it:

1. **Media Session action handlers.** The bridge wraps
   `navigator.mediaSession.setActionHandler` at document start and records the
   handlers the page installs, then calls them. This is the page's own code —
   the same entry point the keyboard's media keys use — so the site's transport
   UI stays in step. YouTube Music and VK Music register handlers; Yandex Music
   does not.
2. **The site's own transport button**, restricted to the bar pinned to the
   bottom of the window so a label match cannot land on a track row.
3. **The media element itself**, used only after the first two are observed not
   to have changed the playback state within 220 ms.

To reach route 3 the bridge patches `HTMLMediaElement.prototype.play` and
`.load` to record the elements the page drives. This is necessary because a
player may create an `Audio` object and never insert it into the document, in
which case no DOM query can find it — Yandex Music does exactly that, which is
why its transport and progress bar did not work at all. The patch records
element references only; it does not alter arguments, return values, or
behaviour, and it forwards every call unchanged.

Play versus pause is decided by the application, not inferred in the page.
`WKWebView.requestMediaPlaybackState` is WebKit's own answer — the same state it
publishes to the system's Now Playing controls — and the resulting intent is
handed to the bridge. If the page ignores a pause, `pauseAllMediaPlayback`
stops the audio the way the system transport does. Both are public WKWebView
API. No private Now Playing framework is linked, loaded, or consulted, and the
Music module still requires no Accessibility permission.

## Diagnostics

The bridge reports its own status lines — which site profile matched, whether a
media element was found, which transport route took effect — to the system log.
These are strings Impuls composes; they contain no page content.

Page-authored output is different. Forwarding `window.onerror`,
`unhandledrejection` and `console.error` repeats whatever the site chose to
print, so it is off unless the user sets `music.webInspector`, the same default
that makes the web view attachable from Safari's Web Inspector. Both are off by
default and neither is needed for playback.

## Playback policy

`mediaTypesRequiringUserActionForPlayback` is now empty. The gesture WebKit was
waiting for is the button press in the Impuls panel, which the panel cannot
forward into the web content process. This lets the panel's own transport work;
it does not let a page start audio on its own, because nothing autoplays until
Impuls or the user asks.

## Removed source

Spotify is gone. Its web player decrypts through Widevine, which WebKit does
not implement, so an embedded tab can authenticate but never produce sound. A
stored `spotifyWeb` selection falls back to Apple Music.

## Known limitations

Unchanged from 1.3.0, plus: Google may still refuse sign-in inside an embedded
web view regardless of the user-agent string. When it does, Impuls surfaces the
provider's own message rather than pretending the source is idle. Impuls must
not respond by harvesting tokens, reverse-engineering protected APIs, or adding
private macOS media frameworks.
