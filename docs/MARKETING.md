# Рекламная аналитика лендинга Impuls

Лендинг не загружает внешнюю аналитику по умолчанию. Разметка уже генерирует
стабильные события, которые можно подключить к Яндекс Метрике, Google Tag Manager
или другой системе без изменения кнопок.

## События

| Событие | Когда возникает | Рекомендуемая цель |
|---|---|---|
| `impuls_download_click` | Клик по скачиванию DMG | Основная конверсия |
| `impuls_demo_click` | Переход к интерактивной демонстрации | Микроконверсия первого экрана |
| `impuls_github_click` | Переход к исходному коду из блока доверия | Микроконверсия доверия |
| `impuls_releases_click` | Переход к списку релизов | Микроконверсия |
| `impuls_feedback_click` | Переход к форме обратной связи | Намерение оставить отзыв |
| `impuls_faq_open` | Открытие вопроса в FAQ | Вовлечённость |
| `impuls_demo_module` | Ручной выбор модуля в демонстрации | Интерес к функциям |
| `impuls_install_view` | Просмотр инструкции установки | Намерение установить |
| `impuls_hash_copy` | Копирование SHA-256 | Доверие / техническая проверка |
| `impuls_scroll_depth` | Достижение 25, 50, 75 или 90% страницы | Глубина просмотра |
| `impuls_release_loaded` | Получены данные актуального GitHub Release | Техническая диагностика |

Событие скачивания содержит `placement` со значением `header`, `hero`, `final`
или `mobile-sticky`. В payload также попадают присутствующие в URL параметры `utm_source`,
`utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `gclid` и `yclid`.

## Google Tag Manager

После установки контейнера создать триггер типа **Custom Event** с именем
`impuls_download_click` и назначить его основной конверсией рекламной кампании.
Остальные события можно использовать для аудиторий и диагностики воронки.

## Яндекс Метрика

После установки стандартного счётчика определить его ID до основного скрипта
лендинга:

```html
<script>window.IMPULS_YM_ID = 12345678;</script>
```

Затем создать JavaScript-цель с идентификатором `impuls_download_click` и
использовать её как конверсию в Яндекс Директе.

## Перед включением счётчиков

Обновить каноническую политику: указать конкретного поставщика аналитики,
обрабатываемые данные, срок хранения и способ отказа. При необходимости добавить
механизм согласия до загрузки необязательных тегов. Само приложение Impuls и его
модель локальной обработки данных от сайта не зависят.

Править нужно источник, а не результат. Публикуемая политика живёт по адресу
`/privacy/` и генерируется из `Scripts/site-privacy-locales/*.json` и
`Scripts/site-privacy-template.html` официальным путём репозитория;
`docs/site-privacy.html` — это оставшийся редирект на `/privacy/`, а не текст
политики, и редактировать его бессмысленно. Сгенерированные локализованные
страницы руками не правятся. Канонический контракт — [Website Legal and Privacy
Localization](../knowledge-base/07-web/legal-privacy.md).

## Аналитика обратной связи

Impuls 1.2.6 не добавляет телеметрию. Аналитическая единица — только обращение,
которое пользователь сам опубликовал в GitHub. Встроенный отчёт содержит
стабильные поля `Category`, `Area`, `Frequency` и `Rating`; для посетителей
репозитория доступны эквивалентные формы проблемы, идеи и общего отзыва.
Все формы используют сопоставимые измерения раздела, частоты, оценки и версии;
свободные неструктурированные issues отключены. Отсутствие обращений нельзя
интерпретировать как отсутствие проблем: до появления достаточной выборки это
только отсутствие наблюдений, а не подтверждённая удовлетворённость.

Рекомендуемый еженедельный срез:

| Метрика | Управленческое применение |
|---|---|
| Количество обращений по категориям | Отделить дефекты от запросов развития |
| Проблемы по разделам приложения | Найти технические зоны с наибольшим трением |
| Частота сценария | Не переоценивать редкие, но громкие запросы |
| Медианная пользовательская оценка | Следить за общим качеством без скрытого опроса |
| Доля повторяемых проблем | Приоритизировать воспроизводимые дефекты |
| Время до первого ответа и закрытия | Контролировать качество работы с обратной связью |

Свободный текст следует группировать по проблеме пользователя, а не по
предложенной им реализации. Не публиковать сводки, из которых можно восстановить
личность автора, и не переносить в аналитику персональные или конфиденциальные
данные из обращения.
